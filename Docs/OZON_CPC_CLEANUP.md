# Ozon CPC sync: лист `СРС`

## Назначение

`ozon_cpc_cleanup.py` читает лист `СРС`, получает метрики `день/неделя/месяц` из
Ozon Performance API и автоматически останавливает SKU/кампании, перешагнувшие
пороги, заданные в листе.

Структура листа `СРС` (A–Y):

| Колонка | Поле | Источник |
| --- | --- | --- |
| A | art | статичный (не трогается) |
| B | model | статичный (не трогается) |
| C | brand | статичный (не трогается) |
| D | pic | статичный (не трогается) |
| E | SKU OZON | первичный ключ SKU |
| F | CAMPAIN ID | первичный ключ кампании |
| G | CAMPAIN NAME | `title` кампании |
| H | Расход день | отчёт `Расход, ₽, с НДС`, период «день» |
| I | Расход неделя | отчёт, период «неделя» |
| J | Расход месяц | отчёт, период «месяц» |
| K | Показы день | `Показы` |
| L | Показы неделя | `Показы` |
| M | Показы месяц | `Показы` |
| N | Клики день | `Клики` |
| O | Клики неделя | `Клики` |
| P | Клики месяц | `Клики` |
| Q | CTR, % месяц | `CTR, %` |
| R | Средняя стоимость клика месяц | `Средняя стоимость клика, ₽` |
| S | Продано месяц | `Продано товаров` |
| T | ДРР в продвижении месяц | `ДРР в продвижении, %` |
| U | Бюджет | `budget` (fallback `dailyBudget`) |
| V | Корзины месяц | `Добавления в корзину` |
| W | Статус | `state` кампании |
| X | Фильтр клики день | порог, заданный пользователем |
| Y | Фильтр ДРР месяц | порог, заданный пользователем |

`weeklyBudget` намеренно не используется: у текущих кампаний это технический
лимит, а не явный бюджет.

## Поток

1. Прочитать строки `СРС` со связкой `SKU OZON` + `CAMPAIN ID`; пропустить строки
   без `art` (по ним не нужна ни аналитика, ни действия).
2. Запросить все SKU-кампании из Ozon Performance API
   (`GET /api/client/campaign?advObjectType=SKU`).
3. Из всех кампаний Ozon выбрать те, что присутствуют в `СРС`, — для них
   получить отчёты за день/неделю/месяц, состав товаров
   (`GET /api/client/campaign/{id}/v2/products`) и метаданные для записи
   `CAMPAIN NAME` / `Бюджет` / `Статус`.
4. Сгенерировать отчёты `POST /api/client/statistics` с `groupBy=NO_GROUP_BY`
   (одна строка на SKU за период, как требует новая структура листа).
5. Дождаться `GET /api/client/statistics/{UUID}` со `state=OK`.
6. Скачать отчёт `GET /api/client/statistics/report?UUID=...` (CSV или ZIP).
7. Записать метрики `день/неделя/месяц`, `CAMPAIN NAME`, `Бюджет` и `Статус`
   в `СРС` (`--write-sheet`).
8. Для строк, у которых `Клики день >= Фильтр клики день`
   **или** `ДРР месяц >= Фильтр ДРР месяц` и чья кампания сейчас в статусе
   `CAMPAIGN_STATE_RUNNING` и является CPC-кампанией, подготовить кандидатов:
   - если SKU всё ещё в составе кампании — `delete` (удалить SKU);
   - если SKU уже нет в составе кампании — `skip_not_in_campaign`.
9. Перед live-удалением повторно проверить состав кампании. Если удаление SKU
   не удалось, отключить всю кампанию
   (`POST /api/client/campaign/{id}/deactivate`).
10. Кандидаты по неактивным кампаниям отбрасываются — останавливать нечего.

`groupBy=NO_GROUP_BY` возвращает одну строку на SKU, агрегированную за период.
Для дня, недели и месяца границы рассчитываются в московском времени
(`period_range`); дневной период — сегодня, недельный — последние 7 дней,
месячный — с первого числа месяца.

Ozon может формировать статистику дольше пяти минут. Скрипт ждёт до 15 минут по
умолчанию (`180 × 5 секунд`). Параметры можно изменить через
`OZON_CPC_REPORT_MAX_ATTEMPTS` и `OZON_CPC_REPORT_SLEEP_SECONDS`.

## Режимы запуска

Из корня проекта:

```bash
cd /Users/vladimirgrebennikov/Code/Checksheets_Project/Checksheets

# Безопасный режим: отчёты собраны, план кандидатов выведен, но в Google
# Sheets ничего не записано и SKU/кампании не остановлены.
./.venv-etm-export/bin/python ozon_cpc_cleanup.py

# Получить метрики день/неделя/месяц + CAMPAIN NAME/Бюджет/Статус в СРС.
./.venv-etm-export/bin/python ozon_cpc_cleanup.py --write-sheet

# Live-режим: записать метрики и применить фильтры (delete/deactivate).
# Требует явного защитного флага.
OZON_CPC_CONFIRM_DELETE=YES \
  ./.venv-etm-export/bin/python ozon_cpc_cleanup.py --write-sheet --apply
```

`--apply` без `OZON_CPC_CONFIRM_DELETE=YES` завершится ошибкой. Без `--apply`
всегда выполняется dry-run.

## Планирование каждые 30 минут

Периодический LaunchAgent пока **не включён**. Для включения live-автоматизации
требуется отдельное подтверждение, потому что она будет регулярно удалять SKU
из рекламных кампаний. Перед включением проверить один dry-run и один ручной
запуск с `--write-sheet` без `--apply`.

## Проверки

```bash
./.venv-etm-export/bin/python test/test_ozon_cpc_cleanup.py -v
./.venv-etm-export/bin/python -m py_compile ozon_cpc_cleanup.py test/test_ozon_cpc_cleanup.py
```

Тесты проверяют:

- границы периодов в московском времени;
- формат payload `POST /api/client/statistics` (RFC3339, `NO_GROUP_BY`);
- парсинг CSV/ZIP отчёта, агрегацию SKU;
- правило `Бюджет` (без `weeklyBudget`);
- маппинг всех 17 метрик/служебных колонок листа `СРС` при записи;
- фильтрацию кандидатов по дневным кликам и месячному ДРР;
- защиту от удаления SKU, которого уже нет в кампании;
- фильтрацию строк `СРС` без `art`.
