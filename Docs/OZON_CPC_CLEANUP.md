# Ozon CPC sync: лист `СРС`

## Назначение

Два скрипта обслуживают лист `СРС`:

- **`create_ozon_cpc_campaigns.py`** — для каждой строки листа создаёт
  CPC-кампанию с названием `я {art}`, бюджетом 2000₽/нед, размещением
  `PLACEMENT_SEARCH_AND_CATEGORY` и автостратегией `TARGET_BIDS`. SKU из
  строки добавляется в кампанию, кампания активируется, новый `CAMPAIN ID`
  записывается в ту же строку листа.
- **`ozon_cpc_cleanup.py`** — читает лист `СРС`, получает метрики
  `день/неделя/месяц` из Ozon Performance API и останавливает SKU/кампании,
  перешагнувшие пороги `Фильтр клики день` / `Фильтр ДРР месяц`.

## Структура листа `СРС` (A–AC)

| Колонка | Поле | Источник |
| --- | --- | --- |
| A | art | статичный (не трогается) |
| B | model | статичный (не трогается) |
| C | brand | статичный (не трогается) |
| D | pic | статичный (не трогается) |
| E | SKU OZON | первичный ключ SKU |
| F | CAMPAIN ID | первичный ключ кампании (создаётся/обновляется) |
| G | CAMPAIN NAME | `title` кампании |
| H | Расход день | отчёт `Расход, ₽, с НДС`, период «день» |
| I | Расход неделя | отчёт, период «неделя» |
| J | Расход месяц | отчёт, период «месяц» |
| K | Показы день | `Показы` |
| L | Показы неделя | `Показы` |
| M | Показы месяц | `Показы` |
| N | Клики день | `Клики` |
| O | Клики неделя | `Клики` |
| P | Клики месяц | `Клики` |
| Q | CTR, % месяц | `CTR, %` |
| R | Средняя стоимость клика месяц | `Средняя стоимость клика, ₽` |
| S | Продано месяц | `Продано товаров` |
| T | ДРР в продвижении месяц | `ДРР в продвижении, %` |
| U | Бюджет | `budget` (fallback `dailyBudget`) |
| V | Корзины месяц | `Добавления в корзину` |
| W | Статус | `state` кампании |
| X | Фильтр клики день | порог, заданный пользователем |
| Y | Фильтр ДРР месяц | порог, заданный пользователем |
| Z | Включение/отключение компании | переключатель, заданный пользователем |
| AA | ФБО | вспомогательное поле |
| AB | ПРОГРУЗ | вспомогательное поле |
| AC | Продажи в продвижении | `Продажи в продвижении, ₽` из Performance API, период «месяц» |

Колонка `Продажи в продвижении` разрешается по заголовку, поэтому скрипт не
зависит от её буквенной позиции и не сдвигает пользовательские поля.

`weeklyBudget` намеренно не используется в `Бюджет`: у текущих кампаний это
технический лимит, а не явный бюджет.

## Создание кампаний

`create_ozon_cpc_campaigns.py` для каждой строки с `art` и `SKU OZON`:

1. Создаёт кампанию
   `POST /api/client/campaign/cpc/v2/product` с телом
   `{title: "я {art}", weeklyBudget: "2000000000", placement: "PLACEMENT_SEARCH_AND_CATEGORY", productAutopilotStrategy: "TARGET_BIDS"}`.
2. Добавляет SKU
   `POST /api/client/campaign/{id}/products` с `{"bids":[{"sku":..., "bid":"0"}]}`.
3. Активирует `POST /api/client/campaign/{id}/activate`.
4. Одним batched-апдейтом записывает новые `CAMPAIN ID` строго в исходные
   строки (например, `F1052`, `F1055`), не затрагивая уже заполненные строки.

Скрипт создаёт кампании только для строк с `art` + `SKU OZON` и пустым
`CAMPAIN ID`. Повторный запуск не создаёт дубликаты. Плановый LaunchAgent
запускает этот поиск каждые 15 минут, а затем выполняет обычную CPC-аналитику.

## Аналитика и остановка (`ozon_cpc_cleanup.py`)

1. Прочитать строки `СРС` со связкой `SKU OZON` + `CAMPAIN ID`; пропустить
   строки без `art` или без `CAMPAIN ID` (по ним не нужна ни аналитика, ни
   действия).
2. Запросить все SKU-кампании
   `GET /api/client/campaign?advObjectType=SKU`.
3. Из всех кампаний Ozon выбрать те, что присутствуют в `СРС`, — получить
   состав товаров `GET /api/client/campaign/{id}/v2/products` и метаданные
   `title`/`state`/`budget`.
4. Сгенерировать отчёты `POST /api/client/statistics` с
   `groupBy=NO_GROUP_BY` (одна строка на SKU за период).
5. Дождаться `GET /api/client/statistics/{UUID}` со `state=OK`.
6. Скачать отчёт `GET /api/client/statistics/report?UUID=...` (CSV/ZIP).
7. Записать метрики `день/неделя/месяц`, `CAMPAIN NAME`, `Бюджет` и
   `Статус` в `СРС` (`--write-sheet`).
8. Из строк с `Фильтр клики день > 0` или `Фильтр ДРР месяц > 0` подготовить
   кандидатов, если порог перейдён и кампания сейчас в статусе
   `CAMPAIGN_STATE_RUNNING` и является CPC:
   - SKU всё ещё в составе кампании — `delete`;
   - SKU уже нет — `skip_not_in_campaign`.
   Если оба фильтра равны 0 — фильтрация отключена, строка пропускается.
9. Перед live-удалением повторно сверить состав кампании. Если удаление SKU
   не удалось, отключить всю кампанию
   `POST /api/client/campaign/{id}/deactivate`.
10. Кандидаты по неактивным кампаниям отбрасываются — останавливать нечего.

`groupBy=NO_GROUP_BY` (или `groupBy=DATE`) используется для получения
статистики за период. Границы периодов рассчитываются в московском времени
(`period_range`):
- **день** — сегодня (`today`);
- **неделя** — 7 завершённых дней по вчерашний день включительно (`yesterday - 6 days` .. `yesterday`);
- **месяц** — 31 день по вчерашний день включительно (`yesterday - 30 days` .. `yesterday`, например при сегодня 06.09 период 06.08–05.09).
Ozon может формировать статистику дольше пяти минут; скрипт ждёт до 15 минут
по умолчанию (`180 × 5 секунд`). Параметры: `OZON_CPC_REPORT_MAX_ATTEMPTS` и
`OZON_CPC_REPORT_SLEEP_SECONDS`.

## Ставки CPC (`set_cpc_bids.py`)

Колонка `AD` — `Размер ставки` — задаёт ставку в рублях для соответствующей
пары `SKU OZON` + `CAMPAIN ID`. Поддерживаются значения вроде `8`, `16` и
`8,50`. Пустая ячейка не меняет ставку; некорректное или неположительное
значение останавливает запуск до любых записей. Сначала скрипт сравнивает
ставку с Ozon, затем отправляет только отличающиеся значения через
`PUT /api/client/campaign/{id}/products` и проверяет результат.

## Режимы запуска

Из корня проекта:

```bash
cd /Users/vladimirgrebennikov/Code/Checksheets_Project/Checksheets

# Создать кампании + записать CAMPAIN ID (без аналитики)
./.venv-etm-export/bin/python create_ozon_cpc_campaigns.py --skip-analytics

# Полный запуск: создать кампании, записать CAMPAIN ID, вывести аналитику
./.venv-etm-export/bin/python create_ozon_cpc_campaigns.py

# Плановый режим: создать отсутствующие и записать аналитику
./.venv-etm-export/bin/python create_ozon_cpc_campaigns.py \
  --analytics-rotation-batches 2 --analytics-write-sheet \
  --analytics-stop-on-filter

# Только аналитика (dry-run)
./.venv-etm-export/bin/python ozon_cpc_cleanup.py

# Проверить план ставок из AD без изменения Ozon
./.venv-etm-export/bin/python set_cpc_bids.py

# Применить ставки из AD
./.venv-etm-export/bin/python set_cpc_bids.py --apply

# Записать метрики в СРС (без действий)
./.venv-etm-export/bin/python ozon_cpc_cleanup.py --write-sheet

# Live-режим (запись метрик + остановка по фильтрам)
OZON_CPC_CONFIRM_DELETE=YES \
  ./.venv-etm-export/bin/python ozon_cpc_cleanup.py --write-sheet --apply
```

`--apply` без `OZON_CPC_CONFIRM_DELETE=YES` завершится ошибкой.

## Замечание по объёму

Создание сотен кампаний и запуск полной аналитики по ним занимает десятки
минут: ~2–3 сек на строку при создании и ~1–2 мин на каждый batched-отчёт
(10 кампаний) при аналитике. На большом листе (сотни строк) рекомендуется:

- сначала `create_ozon_cpc_campaigns.py --limit N --skip-analytics` для
  валидации;
- затем полный запуск;
- аналитику для свежесозданных кампаний разумно запускать через сутки,
  когда в отчётах появятся данные.

## Проверки

```bash
./.venv-etm-export/bin/python test/test_ozon_cpc_cleanup.py -v
./.venv-etm-export/bin/python -m py_compile ozon_cpc_cleanup.py \
  create_ozon_cpc_campaigns.py test/test_ozon_cpc_cleanup.py
```

Тесты проверяют:

- границы периодов в московском времени;
- формат payload `POST /api/client/statistics` (RFC3339, `NO_GROUP_BY`);
- парсинг CSV/ZIP отчёта, агрегацию SKU;
- правило `Бюджет` (без `weeklyBudget`);
- маппинг всех 17 метрик/служебных колонок листа `СРС` при записи;
- фильтрацию кандидатов по дневным кликам и месячному ДРР;
- пропуск строк, у которых оба фильтра = 0;
- защиту от удаления SKU, которого уже нет в кампании;
- фильтрацию строк `СРС` без `art`.
