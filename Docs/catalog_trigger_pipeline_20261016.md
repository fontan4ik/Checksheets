# Каталоги Ozon и WB: автоматическое обновление

`Flow_Каталоги__Автообновление.js` управляет цепочкой `ТЕСТ A/U → ТЕСТ карточки → ТЕХ данные wb`. Установка: `installMarketplaceCatalogTriggersAndRefresh`. Постоянный обработчик `refreshMarketplaceCatalogs` каждые 5 минут возобновляет незаконченный шаг. После полного цикла следующий начинается через 12 часов, чтобы полные каталоги не расходовали общую суточную квоту триггеров ежечасно. Два собственных триггера `syncOfferIdWithProductId` и `updateProductsV2` заменяются одним; имена функций и чужие триггеры сохраняются. Другие триггеры не изменяются.

Ozon запрашивает все товары с `visibility: ALL`. SKU/изображения берутся из v3 product/info/list, бренд и модель — из v4 attributes. Прогресс не сбрасывается из-за добавления товаров в конец таблицы.

Колонки карточки записываются одним Sheets REST `values:batchUpdate`, используя уже выданный OAuth-токен Apps Script. Текстовые литералы экранируются от преобразования в числа/даты, ведущие нули сохраняются, IMAGE и прежние формулы остаются формулами. При 403/404 используется штатная запись SpreadsheetApp и постоянный лимит 4000 строк вместо 8000; успешный REST-запрос автоматически восстанавливает обычный лимит. Результат этапа содержит nextIndex/total/writeMode для проверки фактического прогресса. Проверка: `test/test_ozon_products_atomic_write.js`.

WB сохраняет промежуточные страницы в `_WB_TECH_CATALOG_STAGE` отдельной приватной таблицы `Checksheets WB catalog staging`, затем одним запросом публикует полный каталог. Служебная таблица создаётся один раз и переиспользуется; её ID хранится в `wb_tech_stage_spreadsheet_id`. Старый локальный checkpoint переносится вместе с курсором, исходный лист остаётся резервной копией. Это отделяет частые промежуточные записи от пересчёта основной книги. Ошибка сети, HTTP, JSON или курсора не приводит к публикации частичного каталога. Диспетчер не создаёт временные триггеры и не расходует их лимит. Отдельный ручной updateWBTechDataSheet поддерживает продолжения.

Промежуточный WB-лист расширяется блоками по 10 000 строк, чтобы не запускать структурный пересчёт на каждой странице. До 10 страниц / 1000 строк накапливаются в памяти и записываются одним блоком; курсор сохраняется только после SpreadsheetApp.flush. Неуспешная запись повторяется со старой контрольной точки. Диспетчер берёт семиминутную аренду исполнения под script lock: ручной и автоматический запуск не перезаписывают фазы друг друга. После аварийного шестиминутного завершения аренда истекает сама. Ошибка служебного листа состояния не отменяет успешный шаг загрузки.

Служебный `_CATALOG_STATUS` скрыт, layout A:B фиксирован: ключ/значение. Содержит фазу, время, последний результат, ошибку и фактические собственные триггеры. Формулы StreamSupps не переписываются.

Проверки: test/test_catalog_pipeline.js, test/test_wb_tech_catalog.js, test/test_ozon_catalog_trigger_resume.js, test/test_ozon_products_resume.js. Деплой с общей блокировкой watcher, резервной копией и обратным чтением 48 файлов выполнен 16.10.2026.

- `List_ТЕСТ__A_U__ProductId_Ozon.js`: полный каталог ALL, сохранение прогресса и добавление недостающих артикулов.
- `List_ТЕСТ__C_E_V_X_Y__Товары_Ozon.js`: объединение полей v3/v4, сохранение формул, пакетная запись и адаптивный резервный размер.
- `List_ТЕХ_данные_wb__Таблица__WB.js`: полная выгрузка WB с контрольными точками и публикацией после завершения.
- `Flow_Каталоги__Автообновление.js`: установленный общий триггер, последовательность этапов и защита от перекрытия запусков.
