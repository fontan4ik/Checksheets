`run_marketplace_worker.sh` запускает существующие локальные модули поставщиков последовательно **внутри одной площадки**. Площадки работают параллельно, с отдельным lock на площадку. Ошибка одного поставщика не отменяет отправку остальных; воркер завершится с кодом 1 после всех попыток. Исходные остатки продолжают подготавливать локальные Python скрипты: RS дополнительно в 13:45, Feron в 14:00 и 23:10, ETM в 22:55. Порядок даёт время на обновление источников перед чтением `StreamSupps`; выгрузчики отправляют именно значения этого листа. Почасовое задание CDEK обновляет лист `СДЕК TR`; отдельные marketplace-задания передают остатки на Ozon и Яндекс по расписанию.

На WB сохранён `wb_stock_audit.js`: запись подготовленных батчей, контроль давности снимка и результаты по каждому `chrtId` при разделении 409. Telegram токен и chat binding прежние; ошибки локальных модулей вызывают действующие алерты.

Post-check RS на Ozon читает не более 100 offer ID за запрос, потому что API может вернуть несколько строк складов на один товар и обрезать большой ответ по `limit=1000`. С отправленным остатком сравнивается `free_stock`. Товары с ответами `NOT_FOUND_ERROR`, `NOT_PASS_MODERATION` и `PRODUCT_IS_NOT_CREATED` фиксируются как недоступные и не считаются сбоем синхронизации; остальные ошибки записи остаются аварийными. Проверяются оба склада RS: резерв и Москва.

Ручной запуск одного воркера: `./run_marketplace_worker.sh ozon`, `wb` или `yandex`. Логи: `logs/marketplace_<площадка>_YYYYMMDD.log`. Задания: `com.checksheets.marketplace_ozon`, `com.checksheets.marketplace_wb`, `com.checksheets.marketplace_yandex`. Старые задания `sync_etm_stocks`, `sync_feron_stocks`, `sync_rs_stocks` сняты с launchd и постоянно отключены через `launchctl disable`, чтобы не было повторных отправок после перезагрузки.

Яндекс для остальных поставщиков сейчас выполняется кодом Apps Script. Эти потоки не переносились в локальный воркер, поскольку локального отправителя для них нет.
