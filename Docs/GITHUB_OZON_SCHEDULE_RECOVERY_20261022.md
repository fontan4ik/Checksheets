# Восстановление GitHub и защита Ozon Performance, 22 октября 2026

## Причины

1. Пустой `.git/index.lock` с датой 12 октября не имел владельца и блокировал
   автоматические коммиты. Файл сохранён в резервной копии и удалён под общей
   блокировкой синхронизатора после повторной проверки владельцев и процессов Git.
2. В 27 неопубликованных коммитах уже находились большие журналы API, вплоть
   до 390 МБ на версию. Кроме того, старая выборка для следующего коммита
   включала около 5,3 ГБ диагностических данных. Это не могло штатно загрузиться
   в GitHub.
3. Скрипт ставок каждые 15 минут выбирал все ранее ошибочные строки: до 952
   из 1932 при нуле изменений в таблице. За последние 96 запусков было выбрано
   67990 строк, не считая дополнительных PUT и проверочных GET.
4. Общий лимит Ozon `100000 request per 24h` не останавливал всю пачку.
   Ошибка превращалась в построчную и увеличивала очередь повторов.
5. Реальный ответ PUT для части ставок — HTTP 400 «Ставка не входит в диапазон
   допустимых значений». Прежний код скрывал тело ответа как `put_failed`.

## GitHub

- Добавлено консервативное восстановление старой пустой блокировки: возраст
  не менее часа, отсутствие владельцев и активных Git-писателей, проверка
  inode/metadata перед удалением, резервная копия. Неясные/непустые/свежие
  блокировки не удаляются; dry-run не меняет блокировки.
- Генерируемые выгрузки, копии production-скриптов с ключами, локальные runtime
  и большие файлы исключены из автоматических коммитов. Исходники, тесты
  и объявленные фикстуры сохранены в выборке.
- Изменённые ссылки на вложенные репозитории без опубликованного child HEAD
  не отправляются как недоступные другим пользователям Git-ссылки.
- Такие локальные ссылки не мешают получать независимые обновления корневого
  проекта. Синхронизатор не выполняет рекурсивный checkout вложенных репозиториев;
  конфликт удалённого обновления той же ссылки откладывается без изменения данных.
- Исходная локальная история сохранена в ветке
  `codex/github-recovery-before-20261022`. Данные рабочего каталога сохранены;
  исходный Git-индекс и staged diff сохранены в диагностическом каталоге.
- Новый коммит построен поверх существующего `origin/main` с исходниками
  рабочего каталога. Проверены размеры всех новых Git-блобов и отсутствие
  новых литералов ключей в выбранных исходниках. Отправлено обычным push,
  без force push и без публикации резервной ветки.
- Первый восстановленный коммит: `d4dce4412c50c551f8389ac3cbee596e43a2e408`.

## Ozon Performance

- Без изменений в таблице: до 20 повторов ошибок и 20 аудитных строк за запуск;
  максимум обычной порции — 100 строк. Изменения ставок получают приоритет;
  не попавшие в порцию изменения остаются ожидающими. Ручной full-audit отдельный.
- У повторов независимый курсор, поэтому очередь не возвращается постоянно
  к первым ошибочным товарам.
- Общий межпроцессный предохранитель квоты хранится в `logs/ozon-perf-quota-*.json`.
  При общем лимите пачка прекращается сразу. Состояние касается текущего
  Performance client ID, который в имени файла представлен хешем.
- При наличии используется `Retry-After`; иначе назначается проверка через
  15 минут. После паузы допускается одна проба на все процессы, а не новая
  массовая пачка. Время сброса серверной квоты не предполагается.
- Успешная авторизация не считается восстановлением квоты. Общий лимит
  не смешивается с отдельной квотой асинхронных отчётов.
- Единственное Telegram-уведомление об эпизоде квоты забирается атомарно
  любым увидевшим его процессом; следующие отложенные запуски не повторяют его.
- Неподдерживаемые ставки сохраняются без изменения в таблице и переводятся
  в отдельный `rejected` кэш на 24 часа. Изменение ставки пользователем
  немедленно разрешает новую попытку. Прочие корректные строки обрабатываются.
  Новая ошибка сообщается через существующую Telegram-обёртку; та же ошибка
  при повторной проверке не создаёт повторного уведомления.

Рекламные бюджеты и желаемые ставки автоматически не повышались.
Расписания, Telegram bot/chat и путь проекта Codex сохранены.

## Проверки

- 133 профильных регрессионных теста прошли после итоговых изменений;
  последующие результаты и фактические циклы записываются в итоговый JSON.
- Live read-only проверка двух ставок: одна уже верна, одна требует изменения.
- Live запись двух строк раскрыла постоянную ошибку диапазона ставки.
- Фоновый запуск аналитики: exit 0, дневная аналитика и очередные 10 кампаний
  week/month записаны, курсор продвинут до 940.
- Фоновое переключение кампаний: exit 0, два требуемых изменения выполнены,
  1930 кампаний уже находились в нужном состоянии.
- Фоновая синхронизация ставок: выбрано 40 вместо 952, 20 уже верны,
  20 новых отклонений диапазона сохранены отдельно, обычных ошибок нет.
  Первый такой запуск возвращает 1 для существующего Telegram-оповещения.
- GitHub принял восстановленный коммит. Обычный фоновый цикл завершился
  успешно в 09:38:21 Asia/Dubai. Загрузка Apps Script подтверждена обратным
  pull и сравнением 48 файлов; сохранена резервная копия
  `ChecksheetsSync/backups/20261022T053723Z`.
- Все 26 определений расписаний сохранены; загружены прежние 25 заданий,
  NTC остаётся отключённым.

Диагностика: `test/schedule_recovery_20261022/`. Локальные резервные копии и
выгрузки из этого каталога исключены из GitHub и Apps Script.

Основные изменённые файлы: `scripts/checksheets_github_sync.py`,
