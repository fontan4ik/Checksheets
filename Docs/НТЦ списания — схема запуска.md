# НТЦ списания

## Расчёт

- F — входной физический остаток модели. Скрипт никогда не записывает в F.
- J — **накопленное** ручное списание в упаковках данного артикула. Например, `2` для размера H=`5` означает вычет 10 физических штук из общего запаса модели. Редактирование `2` на `3` увеличивает вычет ещё на одну упаковку; очистка возвращает этот ручной вычет. Формулы пересчитываются сразу, отдельный триггер для ручного ввода не нужен.
- L — итоговое количество упаковок артикула для будущей выгрузки на маркетплейсы. Оно распределяется между кратностями одной модели так, чтобы общие физические штуки не обещались несколько раз. Дубли одинаковой кратности внутри модели получают 0 до исправления данных.
- M — резерв Ozon FBS в физических штуках модели, одинаковый для всех строк модели.
- N = F − M − сумма(J × H) по всем артикулам модели. Отрицательное N показывает превышение доступного запаса.
- G — справочная колонка. I и API остатки Ozon/WB не изменяются.

## Заказы

`installNtcWriteOffs()` создаёт скрытый журнал по `posting_number`, записывает формулы L/N, создаёт минутный триггер и выполняет первую сверку. Повторный запуск установки не создаёт второй триггер. FBS резервируется при появлении в статусе сборки, до фактической сборки. Каждую минуту повторно читаются активные статусы и изменённые статусы: это ловит также частичную отмену без смены статуса. Повторное чтение не удваивает резерв.

Отмена до передачи в доставку освобождает резерв. Если отправление уже передавалось в доставку, статус отмены сам по себе не подтверждает физический возврат, поэтому резерв сохраняется до отдельного учёта фактически принятого возврата. Ошибка API или неизвестный формат не заменяет предыдущий резерв нулями. Заказы других артикулов того же склада игнорируются.

## Перед включением

Нужно подтвердить, содержит ли будущий источник F уже списания по FBS и ручные списания. Если содержит, постоянный вычет из F даст двойное списание; тогда алгоритм нужно переключить на временный резерв до отражения операции в F. Текущая реализация рассчитана на F как на исходный запас **до** этих списаний. `installNtcWriteOffs()` не запускать до подтверждения источника.

Даже после включения L доступный остаток уменьшается только внутри таблицы. Остатки маркетплейсов останутся прежними, поэтому исключить новые сверхзаказы через маркетплейсы до подключения отдельной безопасной выгрузки невозможно.

## Проверки

`node test/test_ntc_write_offs.js` — повторный опрос, отмена до/после отправки, посторонние артикулы, ошибки API и некорректные данные. Реальные запросы Ozon `/v2/warehouse/list` и `/v3/posting/fbs/list` выполнены только на чтение; фильтры статуса и `last_changed_status_date` вернули HTTP 200. Проверка листа выполнена только на чтение.
