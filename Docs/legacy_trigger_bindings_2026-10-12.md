# Обработчики существующих триггеров другого пользователя

Имена `OzonMain` и `WbMain` сохранены. Их код выполняется по уже созданным триггерам; новые постоянные триггеры не создаются. Владельца, авторизацию и расписание чужого триггера изменение кода не меняет. Если чужой триггер отключён, его создатель должен включить его.

`OzonMain` вызывает ту же синхронизацию каталога, что `syncOfferIdWithProductId`: добавляет отсутствующие `offer_id` в `ТЕСТ!A` и обновляет `Product_id Ozon` в U. Общая блокировка предотвращает параллельную запись товарных процессов. Страницы API записываются по одной, затем сохраняется курсор. Бюджет обхода — 3 минуты; следующий штатный запуск любого из двух обработчиков продолжает проход. Повтор после частичной записи A/U исправляет U без повторного добавления артикула. Неполный ответ и остановившаяся пагинация вызывают ошибку; временные HTTP 429/5xx сохраняют прогресс без уведомления о терминальной ошибке.

`WbMain` сохраняет цепочку WB: FBO остатки, суммы заказов, цены, FBS остатки, аналитика заказов и склады. Продолжения остаются под именем `resumeWbMain`. На сбор страниц отведено около 2 минут с минутным запасом на запросы и запись. Сжатые промежуточные данные хранятся в скрытом служебном листе `_WB_TRIGGER_STATE`, общем для владельцев триггеров. Фиксированная структура: A1 — номер шага, A2 — число частей, A3:A — gzip/base64 по 32000 символов. Это служебное исключение из правила пользовательских заголовков. При HTTP 429/5xx и нехватке времени следующий запуск продолжает тот же шаг; при исчерпании квоты временных триггеров используется следующий постоянный WbMain. Старые продолжения соблюдают сохранённое Retry-After. Пагинация Sales Funnel использует limit/offset вместо прежней остановки после первой страницы; источник: https://dev.wildberries.ru/en/openapi/analytics.

Точки входа сохраняют `runWithTelegramAlertGAS_()` и действующие Telegram bindings. Локальные обновления продаж Ozon AQ:AT и отзывов BL не запускаются из этих обработчиков.

Проверка Ozon: `node test/test_ozon_catalog_trigger_resume.js` проверяет привязку `OzonMain`, сохранение страницы и продолжение с нужного курсора, отсутствие дублей, исправление частичной записи, отказ при некорректной пагинации и перенос временной ошибки на следующий запуск. `node test/test_ozon_products_resume.js` проверяет сохранение существующего поведения обогащения карточек.

Проверка WB: `node test/test_wb_trigger_continuation.js` проверяет продолжение FBO без двойного суммирования, восстановление состояния, обработку HTTP 429, шесть шагов, освобождение lock, сохранение формул и переход на постоянный триггер при исчерпании квоты. Изменённые JS-файлы прошли `node --check`; существующие проверки обогащения карточек Ozon и Telegram-обёрток также прошли. Проверки выполняются на моделях GAS и не подтверждают выполнение чужого расписания в Google.

## Загрузка

`clasp status` подтвердил границу загрузки: 47 production файлов, локальные Node/Python helpers и test не загружаются. `clasp push` выполнен успешно; проект скачан обратно во временную папку, все 47 файлов совпали с локальными. Предыдущая облачная версия сохранена в `test/tmp/apps-script-before-legacy-sfwco_96`; локальный снимок перед push сохранён в штатной папке backup за `20261012T024756Z`. Общая блокировка watcher удерживалась на время загрузки и проверки.

Ручное создание новых постоянных триггеров не требуется. Для отключённых чужих триггеров необходимо включение их создателем. Состояние их расписания не проверено этим изменением.

Попытка непосредственного выполнения `OzonMain` через `clasp run-function` отклонена: `Unable to run script function. Please make sure you have permission to run the script function.` Это ограничение прав API выполнения; загрузка и обратное чтение проекта успешны. Выполнение по фактическому чужому расписанию не подтверждено. Новое API deployment/расширение авторизации для этой проверки не создавались.

## Дополнительно: maintainArticleColumn и OzonSKUAndAnalytic

- `maintainArticleColumn` вызывает `updateProductsV2AlertCore_`: C/D/E/V/X/Y по существующим артикулам A. Использует общий lock и курсор карточек с бюджетом 2.5 минуты. Прежняя проверка/текстовый формат колонки A сохранены в ручной `auditArticleColumn`; дополнительный триггер для неё не требуется.
- `OzonSKUAndAnalytic` вызывает `startFetchAndWriteAnalytics_`: I/J/L/AO (месячные и квартальные количества, месячная и годовая сумма заказов). Продолжает существующий проход с бюджетом 3 минуты; HTTP-повторы проверяют оставшееся время и оставляют минутный запас на запрос и сохранение состояния.
- Для совместной работы владельцев триггеров аналитика хранит сжатые данные в скрытом `_OZON_ANALYTICS_STATE`. Фиксированная служебная структура: A1 — JSON metadata (runId, диапазон, число частей и SHA256), A2:A — gzip/base64 по 32000 символов. Старый приватный Drive checkpoint переводится на полный повтор аналитического прохода под lock; файл не меняется и не удаляется. Потерянное или повреждённое состояние вызывает ошибку до получения новых пакетов и записи результатов.

Изменены `Flow_Триггеры__Основные.js`, `List_ТЕСТ__I_J_L_AO__Заказы_Ozon.js`, поясняющий комментарий в `List_ТЕСТ__C_E_V_X_Y__Товары_Ozon.js`, `test/test_additional_legacy_trigger_bindings.js`, `test/test_ozon_analytics_temp_file_recovery.js` и этот документ. Проверки алиасов, времени повторов, совместного checkpoint, безопасной миграции, карточек Ozon, WB продолжений и Telegram-обёрток прошли. Имена триггеров и Telegram bindings сохранены. Прямое выполнение через CLI по-прежнему не подтверждено из-за ограничения прав; его не повторяли.

При завершении общего прохода старое `continueFetchAndWriteAnalytics` другого владельца больше не запускает новый цикл. Это проверено отдельно. Дополнительные привязки загружены в Apps Script; 47 файлов повторно совпали после обратного чтения.
